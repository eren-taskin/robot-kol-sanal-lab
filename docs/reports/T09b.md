# Phase T09b Report — 3D Arm View (`ArmView3D`)

## 1. What Was Changed

- **Vendored `three.js` (`three@0.170.0`, released October 2024)**:
  - Placed `three.module.min.js`, `OrbitControls.js` (with relative import `./three.module.min.js`), and the MIT `LICENSE` file in `src/RobotArm.Web/wwwroot/lib/three/`. No CDN is used at runtime.
- **`src/RobotArm.Web/wwwroot/js/arm3d.js`**:
  - Created Three.js ES module (`window.RobotArm3D`) with $Z$-up world coordinates (`scene.up.set(0, 0, 1)`, `camera.up.set(0, 0, 1)`), `OrbitControls`, and `resetView()`.
  - Built simple geometric primitives at initialization using the exact lengths passed from Core (`OpenManipulatorXGeometry`: `D1 = 0.0595 m`, `A2X = 0.024 m`, `A2Z = 0.128 m`, `L3 = 0.124 m`, `L4 = 0.126 m`): base pedestal, link 1 column, L-shaped link 2 (`a2z` vertical + `a2x` horizontal offset), link 3 forearm, link 4 wrist, two-finger parallel gripper around the tool point, 4 joint spheres with per-joint materials (blue `#1d4ed8` normal, amber `#f59e0b` near limit, red `#dc2626` outside limit), `50 mm` floor grid (`0.8 m` across with `16` divisions), green target crosshair marker, orange detached PickPlace object, and orange attached payload cube.
  - Pre-allocated all meshes, materials, and `THREE.Group` frame nodes (`matrixAutoUpdate = false`) once at `initScene`. Each frame, `updateScene(buf)` sets the four $4 \times 4$ rigid body transforms directly from the `ForwardKinematics.ComputeFrames` buffer (`fg.matrix.set(...)`) with zero kinematics and zero object allocations in JS.
- **`src/RobotArm.Web/Components/ArmView3D.razor`**:
  - Created `ArmView3D` component with the `"2D / 3D"` toggle, `"Görünümü sıfırla"` button, legend, WebGL canvas (`#arm-3d-canvas`), and joint-limit status strip.
  - Pre-allocated `_qBuf`, `_framesBuf` (`Frame[4]`), and `_interopBuf` (`double[62]`) once per component instance; each frame calls the non-allocating `ForwardKinematics.ComputeFrames(_model, q, _framesBuf)` overload and passes `_interopBuf` to JS in a single synchronous `IJSInProcessRuntime.InvokeVoid("RobotArm3D.updateScene", _interopBuf)` call.
- **`src/RobotArm.Web/Components/ArmView.razor` & `src/RobotArm.Web/Pages/Home.razor`**:
  - Added the `"2D / 3D"` toggle to `ArmView.razor` and placed `ArmView3D` next to `ArmView` in `Home.razor` (with 2D remaining the default view).
- **`src/RobotArm.Web/wwwroot/index.html` & `src/RobotArm.Web/wwwroot/css/app.css`**:
  - Registered `<script type="module" src="js/arm3d.js"></script>` and added styling for `.arm-header-left`, `.arm-3d-container`, `.arm-3d-canvas`, and `.arm-3d-hint`.
- **`docs/screenshots/T09b-3d.png`**:
  - Saved screenshot (`258,055` bytes) of the 3D view during a run on `"Dünya – boş kol – noktaya git"`.
- **`PROJECT.md`**:
  - Added `T09b` row in §7 with status `done`.

## 3. Anything Not Done

- **Optional item 6 (ROBOTIS STL meshes)**: Skipped as instructed (*"skip if mesh frames don't match ours and say so"*). In the upstream ROBOTIS `open_manipulator_description` URDF/STL package, the STL mesh coordinate origins include fixed actuator/bracket visual offsets (e.g., `link1` visual origin offset `(0.012, 0, 0.017)` m and base mounting offsets) that do not coincide with the pure joint-axis frames $F_1..F_4$ defined in SPEC §4.1 (`D1 = 0.0595 m` from base origin directly to Joint 2).
